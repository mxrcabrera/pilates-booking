# 4. DETECCIÓN DE REDUNDANCIAS Y MALA COMUNICACIÓN

## Problemas Actuales

### 1. Landing Inexistente
**Problema:** Redirección directa a login sin mostrar valor.
**Impacto:** Alta tasa de rebote. Baja conversión.
**Solución:** Crear landing pública con showcase de producto.

### 2. Features Ocultas
**Problema:** Mascot, Importación Excel IA, Chatbot no se comunican.
**Impacto:** Diferenciadores invisibles para el mercado.
**Solución:** Destacar en hero y feature showcase.

### 3. Planes Confusos
**Problema:** Feature flags no se explican claramente. "WhatsApp" aparece pero no funciona.
**Impacto:** Confusión en decisión de compra.
**Solución:** Reestructurar tabla de planes. Remover features no implementados.

### 4. Onboarding Post-Registro
**Problema:** Selección de rol (Profesor/Alumno) después de crear cuenta.
**Impacto:** Fricción en funnel. Usuarios abandonan antes de ver valor.
**Solución:** Pre-seleccionar rol en landing. "Soy profesor" vs "Soy alumno".

### 5. Trial Bajo Comunicado
**Problema:** Trial existe pero no se destaca en landing.
**Impacto:** Baja conversión a trial.
**Solución:** Hero section centrado en trial. "Prueba gratis 14 días, sin tarjeta."

### 6. Multi-tenancia No Explicada
**Problema:** Feature de roles/equipo existe pero no se comunica.
**Impacto:** Estudios grandes no ven valor en upgrade.
**Solución:** Crear sección específica "Para estudios con equipo".

### 7. Reportes Avanzados Ocultos
**Problema:** Analytics avanzados solo visibles en plan ESTUDIO.
**Impacto:** No se usa como argumento de venta.
**Solución:** Mostrar screenshots en landing. "Disponible en plan Max".

### 8. WhatsApp Feature Flag
**Problema:** Aparece en planes pero no implementado.
**Impacto:** Expectativas no cumplidas.
**Solución:** Remover de comunicación hasta implementar.

# 7. ARQUITECTURA SaaS 2026

## Inspiración: Linear, Resend, Vercel, Notion, Framer

### Principios de Arquitectura de Información

1. **Single Source of Truth**
   - Landing y producto comparten componentes
   - Demo usa componentes reales en modo "read-only"
   - No duplicación de código

2. **Progressive Disclosure**
   - Hero muestra valor inmediato
   - Scroll revela features gradualmente
   - Pricing al final del funnel

3. **Contextual Navigation**
   - Nav cambia según scroll position
   - Breadcrumbs internos
   - Back buttons consistentes

4. **State Management Local**
   - Demo usa localStorage para persistencia
   - No requiere backend para showcase
   - Reset button para limpiar estado

5. **Performance Optimization**
   - Code splitting por route
   - Lazy loading de componentes pesados
   - Skeleton screens para carga

## Implementación Técnica (Sin Código)

### Landing Page Structure
```

# 8. RECORRIDO DE CONVERSIÓN COMPLETO

## Funnel Actual
```
Visitante → / → Redirect a /login → Signup → Onboarding (rol) → Dashboard
```

**Problemas:**
- No ve valor antes de registro
- Onboarding post-registro genera abandono
- No sabe qué es el producto antes de comprometerse

## Nuevo Funnel Propuesto

### Stage 1: Discovery (Landing)
```
Visitante → / (Landing)
  ↓
Ve Hero con Calendario Demo
  ↓
Scrollea Features (Screenshots interactivos)
  ↓
Ve AI Differentiator (Importación Excel + Chatbot)
  ↓
Ve Use Cases (Estudio Individual vs Equipo)
  ↓
Ve Pricing con Trial destacado
```

### Stage 2: Intent (CTA)
```
Click en "Comenzar trial gratis"
  ↓
Modal: "¿Eres profesor o alumno?"
  ↓
[Profesor] → /signup?role=profesor
[Alumno] → /signup?role=alumno
```

### Stage 3: Signup (Con Contexto)
```
/signup?role=profesor
  ↓
Formulario: Email, Password, Nombre
  ↓
[Google OAuth] o [Email/Password]
  ↓
Cuenta creada con rol pre-seleccionado
```

### Stage 4: Onboarding (Simplificado)
```
Usuario autenticado
  ↓

- **Modo demo:** Props booleanas para deshabilitar acciones
- **Componentes compartidos:** Single source of truth
- **Performance optimization:** Code splitting, lazy loading
- **A/B testing:** Validar cambios con datos reales
